# `reports/status/`

Machine-readable status surfaces for the locked runtime/gate layer and the release/catalog layer.

## Mixed ownership inside this directory

- `swarm_runs/` — durable runtime run manifests generated by `scripts/swarm.py`
- `reviews/` — durable Judge review logs generated by `scripts/swarm.py`
- `releases/` — canonical release manifests generated by `scripts/release_assembly.py`

Do not hand-edit generated JSON artifacts in these namespaces.

## Canonical release-manifest rule

- Namespace: `reports/status/releases/`
- Filename pattern: `reports/status/releases/release_<YYYY-MM-DD>.json`
- One canonical manifest exists per UTC release date.
- `reports/catalog.yaml` is rebuilt from the release manifests present in this namespace.

## Operator workflow

- Assemble or refresh a release snapshot:
  - `python scripts/release_assembly.py --release-date <YYYY-MM-DD> --write`
- Verify namespace integrity, artifact hashes, and catalog synchronization:
  - `python scripts/release_assembly.py --check`

## Downstream paper dependency

The final Quarto manuscript sources and render outputs remain reserved for continuation Stage 2 under `reports/paper/`.

`release_assembly.py` therefore records paper outputs in one of two states:

- `pending_stage2` when `reports/paper/build/` has not yet been materialized
- `present` when Stage 2 build artifacts exist and can be hashed into the release manifest
