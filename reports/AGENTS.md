# reports/AGENTS.md — report, status, and release operating rules

## Scope

`reports/` holds durable research outputs plus the machine-readable status and release surfaces that sit downstream of the locked runtime/gate layer.

Treat the repository as shared memory:

- generated artifacts go to stable paths
- README files explain namespaces and policies
- durable JSON/YAML status artifacts are produced by scripts, not by hand edits

## Ownership boundary

- Worker tasks may generate domain outputs under:
  - `reports/validation/`
  - `reports/figures/`
  - `reports/tables/`
- `reports/status/swarm_runs/` is runtime-owned and generated by `scripts/swarm.py`.
- `reports/status/reviews/` is Judge/runtime-owned and generated by `scripts/swarm.py`.
- Operator owns the shared release surfaces:
  - `reports/catalog.yaml`
  - `reports/status/releases/`
  - `reports/paper/build/`

Do not hand-edit generated JSON artifacts in `reports/status/`.

## Generation rules

- Do not manually edit generated figures, tables, validation summaries, swarm run manifests, Judge review logs, or release manifests.
- Prefer stable filenames for figures, tables, validation outputs, and paper build outputs.
- Every non-README artifact under `reports/` must be traceable to:
  - upstream raw and/or processed manifests when empirical data is involved
  - the generating command or script
  - the relevant runtime/review manifests under `reports/status/` when the artifact comes from a swarm task
- Keep namespace documentation in `README.md` files durable and human-readable; keep generated artifacts machine-produced.

## Release assembly

- Build or refresh the canonical release manifest with:
  - `python scripts/release_assembly.py --release-date <YYYY-MM-DD> --write`
- Verify release-manifest naming, artifact hashes, and catalog synchronization with:
  - `python scripts/release_assembly.py --check`
- Canonical release manifests live under `reports/status/releases/` with filename pattern:
  - `release_<YYYY-MM-DD>.json`
- `reports/catalog.yaml` is generated from the release manifests in that namespace. Manual edits to catalog entries will be overwritten by `scripts/release_assembly.py`.

## Stage boundary

- This continuation stage owns the release/catalog layer only.
- Quarto paper source and render surfaces remain under `reports/paper/` and are reserved for continuation Stage 2.
- Until Stage 2 materializes `reports/paper/build/`, release manifests should record paper status as pending rather than inventing manuscript artifacts.
